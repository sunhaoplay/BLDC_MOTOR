# PWM 同步电流采样与波形缓存

当前控制链为 TIM1 OC4REF 上升沿 → ADC1/ADC2 同步注入 → ADC1 完成中断 → 电流换算、编码器角度、Park、电流 PI、SVPWM。每个完整 PWM 周期执行一次电流环，TIM1 更新中断不再执行 FOC。

## 外设配置

| 项目 | 当前值 |
| --- | --- |
| TIM1 | 168 MHz，PSC=0，中心对齐模式 1，ARR=4199，RCR=0 |
| PWM / 电流环 | 约 20 kHz，约 50 µs 一拍 |
| 内部采样触发 | CH4 PWM2，CCR4=4115，TRGO=OC4REF，上升沿 |
| ADC1 注入组 | PC5 / CH15 / U 相，15 cycles |
| ADC2 注入组 | PB1 / CH9 / W 相，15 cycles |
| 双 ADC | Injected simultaneous；ADC1 外部触发，ADC2 保留 CubeMX 的 Auto Injected 设置 |
| ADC 时钟 | APB2 84 MHz / 4 = 21 MHz |
| ADC1 规则组 | CH10 母线、CH14 温度、CH4 电位器，各 144 cycles |
| 慢信号 DMA | 每 20 拍启动一次三通道扫描，DMA_NORMAL，约 1 kHz |
| 中断优先级 | ADC=0；DMA2 Stream0 和 USART1=2 |

CH4 只生成内部参考信号，不使能 CC4E，不输出到 PE14。三相输出只操作 CH1/2/3 及其互补通道的使能位。

中心对齐模式下完整周期严格为 `2 × ARR / 168 MHz`，本配置约为 49.988 µs（20,004.76 Hz）；控制算法仍使用原有名义周期 50 µs。RCR=0 时峰顶和谷底都有更新事件，所以不能在每次更新事件都运行一次 20 kHz 电流环。ADC 触发使用 OC4REF 的上升沿，因此每个完整周期只有一次采样。

`regular_bldcmotor.ioc` 已同步 EOC=sequence、DMA_NORMAL、DMA2 Stream0 中断以及 CCR4=4115。后续重新生成后，确认构建源文件列表仍包含应用源文件及新增的 `Sdrive/foc_wave.c`。

## 采样窗口与电压限制

CCR4 在峰顶前 84 ticks（0.5 µs）产生触发，OC4REF 的高电平宽度约 1 µs。15 cycles 采样阶段约 0.714 µs，加上 12 cycles 转换约为 1.286 µs，不包含触发同步及中断响应延迟。正常情况下进入 ADC 回调时，TIM1 已在向下计数；三相 CCR 使用预装载，应在随后的谷底前写完。

SVPWM 按实际 ARR 映射，当前三相 CCR 限制在 588～3611。最近的三相比较沿与触发点至少相隔 504 ticks（3 µs）；现有死区 100 ticks 约 0.595 µs 会占用这段时间，功率管实际开关沿后的余量需用示波器确认。这里的余量适用于本板串相线霍尔电流传感器的同步采样，并非下桥臂电阻采样窗口重构。

饱和时三相调制量统一缩放，保持电压矢量方向。预留余量后，允许的 CCR 偏移上限约为原满调制的 72%，会降低最大可用电压及高速能力。电流 PI 参数、Id=0 和 Iq=0.3 A 给定沿用原值；尚未针对新的电压限制重新整定 PI 或加入调制饱和反算。

## 上电流程

1. 禁止三相输出，启动编码器、ADC2、ADC1 和 TIM1 内部触发。
2. 等待传感器稳定 100 ms，然后在输出关闭期间累计 1024 组不同的注入采样，计算 U/W 零点。采样正常时校准约需 51.2 ms，250 ms 超时则停机。
3. 执行原有 beta、alpha 两次吸合，在 alpha 保持期间清零编码器，然后停机。
4. 清除 PI 等动态状态，装载中性占空比，再使能输出和电流环，同时开始连续波形采集和发送。

电流换算仍为 `Iu=(OffsetU-RawU)*I_GAIN`、`Iw=(OffsetW-RawW)*I_GAIN`、`Iv=-Iu-Iw`。`I_GAIN=0.018315 A/code` 及传感器方向沿用原工程，需要用已知电流实测核对。三相和为零是 V 相重构的结果，不能单独证明采样或相序正确。

## 实时波形

当前使用 `Sdrive/foc_wave.c` 连续发送三相电流。进入正常电流闭环后开始取数，每 5 次 ADC 控制回调保存一组 `AdcPara.CurU/CurV/CurW`，名义上传频率 4 kHz；按当前实际 PWM 频率约为 4000.95 Hz。三路来自同一拍，单位 A，均已去零点，尚未进行软件低通。V 相由 U/W 重构。

上位机以 VOFA+ 为例：

1. 选择连接开发板的串口，设置 **921600 波特率、8N1**，协议选择 **JustFloat**。
2. 开始接收，在波形窗口选择通道 0、1、2，分别为 U、V、W 相电流。
3. 如果时间轴可以设置采样率，填写约 4000 点/秒，即每点约 0.25 ms。先显示 400～800 点，约为 100～200 ms。
4. 等待转速稳定后判断波形，三相应有相同周期、接近的幅值及约 120° 相移。Id/Iq 没有包含在当前三通道帧中。

帧格式为三个小端 IEEE 754 `float`，随后是 JustFloat 帧尾 `00 00 80 7F`，共 16 字节。该协议是二进制；文本串口终端显示乱码属于预期，不能选择 CSV/FireWater 文本解析协议。发送时按批次到达，时间轴应按采样率计算，不能按 USB/串口批次到达的间隔计算。

16 字节 × 4000 组/秒 = 64000 字节/秒。8N1 下需要约 640000 bit/s，占 921600 名义线路带宽约 69.4%。波特率已同步到 `Core/Src/usart.c` 和 `.ioc`，上位机和串口转换器也需要支持 921600。

## 波形发送的执行开销

ADC 回调中只分频、检查队列容量、保存三个浮点数和帧尾；不执行字符串格式化，不调用串口 HAL，不等待 DMA。128 帧环形队列约占 2 KiB，索引由 ADC 和主循环各自维护，不需要关中断复制数据。

主循环每次最多启动一块 16 帧（256 字节）的 DMA，直接读取队列内存。只有串口完成回调确认发送完，或者中止回调确认 DMA 已停止后，队列才释放这段内存。因此 ADC 不会覆盖 DMA 正在读取的数据。正常约每 4 ms 启动一块，每秒约 250 块，批量发送引入数毫秒延迟；发送持续循环，不会录满一批就停止。主循环应持续调用 `task_loop()`，避免加入较长的阻塞任务。

UART 启动 DMA 时用 BASEPRI 暂时屏蔽优先级 2 及更低的中断，优先级 0 的 ADC 电流环仍可抢占；没有波形数据复制期间的全局关中断。UART TX 的 DMA 半传输中断已关闭，保留发送完成及必要的错误处理。ADC、DMA 和串口仍有非零 CPU/总线开销，实际最大回调时间需在板上用诊断变量验证。

主循环或串口来不及处理时，队列满便丢弃新波形点，并累加丢点计数，不等待、不覆盖旧数据、不停止电流环。TX 错误后先异步中止，再丢弃受影响的块，继续后续发送。正常查看波形时丢点和发送错误计数应保持 0；如果发生丢点，三通道 JustFloat 帧没有携带时间戳，上位机无法自动标出缺失的时间间隔。

调试器设置 `FocWaveEnabled=0` 可暂停取数，队列余量发完后 TX 灯停止；写回 1 后恢复。仍保留 USART1 接收 DMA。为了避免文本破坏二进制帧，波形初始化成功后独占 USART1 发送，`shell_send()` 返回 -1，`shell_send_raw()` / `uart1_msg_send()` 返回 HAL_BUSY，不会把文本混入波形。

分频、队列大小及批量帧数位于 `Sdrive/foc_wave.h`。例如只能用 115200 时，可将分频设为 40（约 500 Hz），并同步修改 `.ioc` 和 `usart.c` 的波特率；观察较快电流时，500 Hz 点数可能不足。初始化会检查上传数据量不超过名义串口带宽的 80%，配置不匹配时只禁用波形，不阻止电机控制启动。

## 调试变量

无法在线调试时，观察板上 LED。蓝灯仍每 500 ms 翻转。进入正常主循环后等待约 1 秒：绿灯常亮表示最近 500 ms 确认有新的 UART 发送完成；否则绿灯熄灭，红灯按下表重复闪烁，每组周期为 4 秒，每次亮/灭各 200 ms，组间有较长停顿。

| 红灯每组次数 | 含义 | 下一步检查 |
| --- | --- | --- |
| 1 | 波形初始化的带宽检查失败 | 确认实际编译的 `usart.c` 为 921600、分频为 5；仅修改 VOFA+ 的波特率不足以通过检查 |
| 2 | 初始化时未取得 UART 发送权 | 检查启动阶段是否还有其他 USART1 发送 |
| 3 | 波形未使能、控制未进入运行态，或尚未入队 | 检查波形初始化和 ADC 中 `FocWaveCapture()` 调用 |
| 4 | 数据已入队，最近 500 ms 没有确认发送完成 | 检查 UART/DMA 状态、DMA2 Stream7 和 USART1 的 IRQ；也可能尚未成功启动 DMA |
| 5 | 最近 500 ms 出现发送启动/传输错误 | 检查 TX DMA 初始化与错误处理 |
| 6 | 有发送进展，但最近 500 ms 队列满而丢点 | 检查主循环阻塞和实际处理能力 |

绿灯正常仅证明 MCU 的发送完成链路在运行，不能证明 USB 转串口和上位机已收到数据。此时若上位机没有数据，优先检查 PB6 TX 到串口转换器 RX 的连接、共地、COM 口是否被占用，以及 921600/8N1 设置。上电对齐期间尚未进入主循环，灯态不用于判断。诊断只在主循环更新 LED，不向二进制串口插入文字、不等待串口、不更改电流环和 PWM。

| 变量 | 正常现象 / 含义 |
| --- | --- |
| `AdcCurrentSamples` | 无故障时每秒增加约 20000 |
| `AdcSlowSamples` | 每秒增加约 1000 |
| `AdcRawU` / `AdcRawW` | 最近一拍的两个注入 ADC 原始码 |
| `AdcFilPara.OffsetCurU/W` | 校零得到的零电流码 |
| `AdcControlCyclesMax` | ADC 应用回调最大 CPU 周期数；除以 168 得到 µs，不包括外层 HAL IRQ 的全部开销 |
| `AdcControlDeadlineMisses` | CCR 写入越过预期谷底的次数，正常应为 0；此项只统计，不直接触发停机 |
| `AdcFault` | 正常为 0；非零时锁存并关闭三相输出，复位后重新校准 |
| `FocWaveEnabled` | 1=连续取数，0=暂停取数并发完队列余量 |
| `FocWaveFault` | 正常为 0；1=分频/波特率带宽不匹配；2=未能取得串口发送权 |
| `FocWaveSamples` | 成功入队的组数，正常每秒增加约 4000 |
| `FocWaveSent` | 完整发送成功的组数，以批次更新，正常接近入队数 |
| `FocWaveDropped` | 队列满而丢弃的组数，正常为 0 |
| `FocWaveTxDropped` | 发送失败或中止而丢弃的组数，正常为 0 |
| `FocWaveTxErrors` | DMA 启动或发送错误的次数，正常为 0 |

`AdcFault` 的 `0x10000` 表示 ADC2 注入结果未就绪；`0x20000` 表示校零超时或校零期间采样异常；`0x40000` 表示慢信号 DMA 启动、完成或 ADC 错误，同时可能带有 HAL ADC 错误码低位。慢信号 DMA 重启时不会调用 `HAL_ADC_Stop_DMA()`，避免连同正在运行的注入采样一起关闭。

同步采样版本此前已验证 SVPWM 输入范围、校零和慢信号分频。此次实时波形通过实际 `foc_wave.c` 和 `usart.c` 的主机测试：模拟 10 秒连续流、协议字节、分频、队列回绕、DMA 内存保持、拥堵丢点、启动失败、异步中止恢复、暂停恢复、BASEPRI 恢复及串口接收。硬件接口使用替身；实际串口连接、触发时刻、传感器增益、控制执行时间及相电流形状仍需板上确认。
